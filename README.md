# 公仆之心 Ver 3.0

> chinese-govermnet-simulator

按《本地单机技术实现细节与模块边界 Draft 02》实现的本地制度仿真。

**运行时不联网、不调用任何 API、不使用任何 LLM。**
世界由 SQLite + 制度规则 + 状态机 + 可复现随机数 + 文本模板驱动。

## 运行

```bash
python app/main.py
```

## 打包成 exe

```bash
python 打包.py
```

产物是 `dist/公仆之心.exe`，单个文件五十来兆，拷给别人就能玩，对方不需要装
Python 和 PySide6。

打包后 `data/` 下的制度规则会被一起打进去，存档写到
`%LOCALAPPDATA%\公仆之心\saves`——exe 可能被放在没有写权限的地方，
所以不写在 exe 旁边。

给别人之前先自检一遍：

```bash
dist\公仆之心.exe --selftest
```

它会在 `%LOCALAPPDATA%\公仆之心\selftest.txt` 写一份报告：数据文件找不找得到、
世界能不能开起来、能不能推进。打包后没有控制台，出了问题只能靠这个看。

首次弹出建角窗口（姓名/性别/干部来源/学历/世界种子），确认后进入 1986 年 7 月 15 日的红山县。

跑测试：

```bash
python -m pytest
```

## 已实现的制度红线

- 岗位不能凭空生成，空缺只能由退休/去世/调动/机构调整产生（§19）
- 任用必须逐级走完状态机，没有任何入口能跳到最后（§34、§69）
- 玩家与 NPC 走同一套任用规则，没有直通车
- 历史称谓不被后来的制度改写：1999 年的副主任科员永远是副主任科员（§26）
- 领导职务与公务员职级是两条并行通道，不合并为单一官阶（时间轴 §33）
- 文本随机与世界随机分流，换一句措辞不改变谁升职（§51）
- 同一存档 + RNG state + 操作序列，结果完全一致（§70）
- 没有自由文本输入：动作只作用于库里真实存在的机构、人和事项（§54、§55）
- 四套班子 + 纪委监委齐备，名单按党委、人大、政府、政协的次序排（蓝图 十六）
- 没有"廉政值"。记的是具体行为，且**违规与发现分离**：1992 年收的礼可能 2022 年才由审计翻出来（§43-44）
- 项目每个环节都留下经手人，十年后查起来能一路追溯（§42）
- 在查期间不予办理退休：案件先了结，否则到龄的人会赶在了结前走掉，撤职落空
- 关系能让事情办得动，但一条都进不了任免条件（§69）
- 党校是履历门槛不是加速器：培训经历与年龄、资历并列为任职条件
- 世界含县、市、省、中央四级，干部可以从科员走到省部级
- 中央委员只在党代会上产生（五年一次），身份与行政级别分开显示
- 总书记必须担任中央职务，1993 年起兼任国家主席（§20 兼任记为非主职）
- 任免的讨论决定在常委会上、项目立项在常务会议上——不上会就卡住
- 退休年龄按层次分档：县处级 60、省部级 65、副国级以上七上八下
